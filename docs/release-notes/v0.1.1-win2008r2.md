# Reqbox 0.1.1 for Windows Server 2008 R2

The **legacy build**: the same application as the main-branch releases, compiled
with **Go 1.20.14** so it still starts on Windows Server 2008 R2 (NT 6.1) and
other pre-Windows-10 systems.

Newer Go toolchains emit binaries that call `ProcessPrng`, which
`bcryptprimitives.dll` does not export before Windows Server 2012. On 2008 R2
such a binary exits immediately without printing anything — no error, no log.
That is the entire reason this release exists.

## What is in the archive

```
reqbox.exe            the server and the embedded web client, one file
LEGACY-WINDOWS.md     why the legacy build exists, and its limits
README.md             normal usage
```

Unpack it anywhere and run `reqbox.exe`. On first start it prints an API token
and a URL that signs you in:

```
msg="API token generated; open this URL once to sign in"
  token=8fK2…  url="http://127.0.0.1:5178/?token=8fK2…"
```

Open that URL and the token is exchanged for a session cookie, then removed from
the address bar. Only the SHA-256 hash is stored, so the plaintext is shown once.
A restart keeps you signed in.

Verify the download:

```powershell
Get-FileHash .\reqbox_0.1.1_windows_amd64_legacy.zip -Algorithm SHA256
# compare with checksums.txt
```

## Compatibility

| System | This build |
| ------ | ---------- |
| Windows Server 2008 R2 (NT 6.1) | **built for it** |
| Windows 7 / 8 / 8.1 | expected to work (same kernel family) |
| Windows Server 2012 / 2012 R2 | works |
| Windows 10 / Server 2016+ | works, but the main-branch build is the better choice |

Every release is checked by `scripts/legacyguard`, which fails the build if the
binary:

1. declares a minimum OS above 6.x,
2. references `ProcessPrng` or `bcryptprimitives.dll`, or
3. imports a DLL that is not known to ship with NT 6.1.

CI runs the same check and then starts the binary on Windows to confirm the
embedded UI is served. See `LEGACY-WINDOWS.md` for the full reasoning.

## What is different from the main-branch release

Only the toolchain and the dependency versions. The application, the database
schema and the UI are identical; the front end is the same build.

| Item | This branch | Main |
| ---- | ----------- | ---- |
| Go | 1.20.14 | 1.24.1 |
| `log/slog` | self-written `internal/logging` | standard library |
| SQLite driver | `modernc.org/sqlite` v1.29.10 | v1.39.1 |

The pins are not cosmetic: raising them makes the branch stop compiling with
Go 1.20, which is why `scripts/check-legacy-pins.ps1` runs in CI.

## Security notes

Same as main, and they matter more on an old server:

- **Stored credentials are plaintext.** The database is restricted to the
  account running it, but anyone who can read the file reads every Bearer token,
  Basic password and API key in it.
- **Go 1.20 is out of support** (since February 2024), as is Windows Server
  2008 R2 (extended support ended January 2020). This build receives no runtime
  security updates from the Go team.
- **Keep it on an isolated internal network.** Do not expose the port to the
  internet. The default listen address is `127.0.0.1`; use `-addr` only if you
  really need remote access, and put TLS in front of it.

## Unverified on real hardware

The binary is verified structurally (see above) but **has not yet been run on a
physical or virtual Windows Server 2008 R2 machine**. Windows Server 2012 R2 was
confirmed on 2026-10-20; 2008 R2 is the next test. If it fails, please report
whether the process exits instantly, and include the output of:

```powershell
.\reqbox.exe -version
```
