Reqbox 0.1.2 for Windows Server 2008 R2 — the first release that actually
**starts** on 2008 R2 and lets you sign in.

`v0.1.1` started, but the front end had no unlock screen: the page loaded,
every API call returned 401, and there was no way to enter the token. This
release fixes that, and removes the two remaining obstacles from a
double-clicked start.

## Highlights

- **You can sign in now.** The unlock screen was missing from the front end —
  the server-side token check had been ported, the page that asks for the token
  had not. The browser opens straight into the app instead of an empty workspace
  with an error toast.

- **The browser opens by itself, already signed in.** The token is printed once
  and never again, so a user who cannot copy it out of the console window is
  locked out permanently. Startup now opens the sign-in link directly.
  `-no-browser` or `openBrowser: false` turns it off. On a restart, where the
  plaintext is gone, it opens the bare address and you land on the unlock screen.

- **`reqbox.yaml` next to the executable.** A double-clicked binary had no way to
  pass a flag, so the port could not be changed at all. Copy
  `reqbox.example.yaml` to `reqbox.yaml` and edit it.

  ```yaml
  server:
    port: 5178
    autoPort: true      # move to the next free port when this one is taken
    openBrowser: true
  ```

  Precedence: **flag > environment variable > file > built-in default**, so an
  existing shortcut that passes `-addr` keeps working. Unknown keys are an
  error rather than silently ignored.

- **A busy port no longer stops startup.** It moves to the next free port and
  logs `requested=... using=...`; the sign-in URL uses the port actually bound.
  `autoPort: false` restores a hard failure if something depends on an exact
  port.

- **The console no longer freezes on a drag-select.** Windows' QuickEdit mode
  paused output when you selected text and turned Ctrl+C into copy. That flag is
  cleared at startup.

## Install

1. Download `reqbox_0.1.2_windows_amd64_legacy.zip` below and unpack it.
2. Run `reqbox.exe` (double-clicking is fine now).
3. Your browser opens, already signed in.

Verify the download:

```powershell
Get-FileHash .\reqbox_0.1.2_windows_amd64_legacy.zip -Algorithm SHA256
# compare with checksums.txt
```

## Compatibility

Built with **Go 1.20.14** as always, because Go 1.21+ emits binaries that call
`ProcessPrng`, which `bcryptprimitives.dll` does not export before Windows
Server 2012 — such a binary exits instantly with no output on 2008 R2.

Every release is checked by `scripts/legacyguard` before publishing: PE minimum
OS must be 6.x, the file must contain no `ProcessPrng` / `bcryptprimitives`, and
imported DLLs must be on an allowlist of libraries that ship with NT 6.1. The
archived `.exe` is unpacked and re-checked after zipping.

| System | This build |
| ------ | ---------- |
| Windows Server 2008 R2 (NT 6.1) | **verified — starts and runs** |
| Windows 7 / 8 / 8.1 | expected to work (same kernel family) |
| Windows Server 2012 / 2012 R2 | works |
| Windows 10 / Server 2016+ | works; the main-branch build is the better choice |

## Still unverified

The three fixes in this release were verified on Windows 10 and by end-to-end
HTTP checks against the real binary, but **not yet re-run on 2008 R2 itself**.
Please confirm on the machine:

1. Double-click `reqbox.exe` — the browser should open already signed in.
2. If it does not, run `reqbox.exe -version`; if that prints nothing, the binary
   did not load and that is the thing to report.
3. Send one request — saving was the step that failed before.
4. Optional: start a second instance and confirm the first one's log shows
   `requested=... using=...` and the browser lands on the new port.

## Security notes

Unchanged, and they matter more on an old server: stored credentials are
plaintext in the database (the file is restricted to the account running it, but
anyone who can read the file reads every token), Go 1.20 is out of support,
and Windows Server 2008 R2's extended support ended in January 2020. Keep this
on an isolated internal network.
