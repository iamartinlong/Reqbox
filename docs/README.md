# 文档索引

本目录存放项目文档与开发过程记录。代码解释「怎么做」，这里解释
「为什么这样做」「还有什么没做」。

## 这里有什么

| 文档 | 用途 | 什么时候看 |
| ---- | ---- | ---------- |
| [TODO.md](./TODO.md) | 待办事项，按优先级排列，含工时估算 | 接手项目、决定下一步做什么 |
| [PLAN.md](./PLAN.md) | 实施计划：分阶段步骤与验收 | 准备动手做某一项时 |
| [DECISIONS.md](./DECISIONS.md) | 决策记录（DR） | 想知道某个设计为何如此、或想推翻它 |
| [CHANGELOG.md](./CHANGELOG.md) | 已完成的改动与修复 | 了解项目演进、排查「什么时候变的」 |
| [DEVELOPMENT.md](./DEVELOPMENT.md) | 本地开发、构建、验证流程 | 第一次跑起来、或搭建环境 |
| [LEGACY-WINDOWS.md](./LEGACY-WINDOWS.md) | Windows Server 2016 之前系统的兼容方案 | 部署到旧版 Windows 服务器 |
## 三条约定

1. **待办要写清验收方式。**
   只写「优化性能」等于没写 —— 无法判断何时算完成。每条 TODO 都应能回答
   「怎么确认它做完了」。

2. **决策要记录「当时的理由」和「什么情况下重新考虑」。**
   记录理由，是为了避免后人不知道背景就推翻；记录重议条件，是为了避免
   把已经过时的决定当成不可动摇的教条。

3. **过程文档面向未来的人，不面向写的人。**
   不写「今天调了很久」，而是写「这个坑的表现、根因、如何避免」。
   读者是三个月后已经忘记细节的自己和同事。

## 与 README 的分工

- `README.md`：面向**使用者**。怎么启动、有哪些功能、API 长什么样。
- `docs/`：面向**维护者**。待办、决策理由、开发流程、变更历史。

避免把维护者向的内容塞进 README —— 使用者不需要知道我们还没做什么。
