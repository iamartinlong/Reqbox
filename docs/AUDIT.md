# 上线审计 · 2026-10-21

针对当前 `main`（`ceb4310`）的一次上线前审计。每一项都经过实测，不只看代码。

## 一、已修复

### A1 · legacy 分支完全没有鉴权（高危）　✅ 已修复

`legacy/win2008r2` 是部署在 Windows Server 2012 R2 上的分支，也是**实际在
运行**的那一个。它**不含**本次鉴权与 ACL 的修正：

| 项 | main | legacy |
| -- | ---- | ------ |
| `internal/server/auth.go` | 有 | **无** |
| `internal/store/acl_windows.go` | 有 | **无** |
| 默认监听 | `:5178` | `:5178` |

实测该分支的行为等同于修复前：无需任何凭据即可读走全部明文凭据。
`sameOriginGuard` 在，但它只防浏览器跨站写，不防直接 `curl`。

**影响**：该服务在旧服务器上运行时，同网段任何人都能拉走所有 token。

**修复**：auth + ACL 已完整移植到 legacy。

| 项 | 状态 |
| -- | ---- |
| `internal/server/auth.go` | 已移植（`slog` → `logging`） |
| `internal/server/handlers_auth.go` | 已移植 |
| `internal/store/acl_{windows,unix}.go` | 已移植 |
| `auth_test.go` / `acl_windows_test.go` | 已移植（18 + 1 个用例） |
| 默认监听 | 改为 `127.0.0.1:5178` |
| `go.mod` | 仅 `x/sys` 由 indirect 提升为直接依赖 |

**验证方式**：用**真实的 Go 1.20.14 工具链**构建并跑全量测试，全部通过；
`check-legacy-pins.ps1` 报告 5 项 pin 全部完好。实测 legacy 二进制：
无 token → 401，带 token → 200，默认只绑回环，ACL 收紧到三个主体。

**过程中发现的一个陷阱**：在本机 Go 1.24 下执行 `go mod tidy` 会把
`go 1.20` 抬到 `go 1.21` 并写入 `toolchain go1.24.1`，直接破坏该分支的
存在前提。这也解释了 `check-legacy-pins.ps1` 为何存在。最终 go.mod 是
手工最小化编辑的，且用 Go 1.20 实测验证——只有 1.20 的结论才可信。

### A2 · 默认监听所有网卡（中危）　✅ 已修复

`:5178` 绑到全部网卡。有 token 保护后不再致命，但把「本机工具」暴露到
整个网段仍然超出多数人的预期。

**修复**：默认改为 `127.0.0.1:5178`。需要局域网访问时显式 `-addr`，
且会打印警告。

**验证**：

| 场景 | 结果 |
| ---- | ---- |
| 不带 `-addr` 启动 | 仅监听 `127.0.0.1` |
| 内网 IP 访问 | 拒绝（000） |
| `-addr 0.0.0.0:5178` | 启动时打印 WARN |
| `TestListensOnLoopbackOnly` | 4 个回环 + 6 个暴露地址全部分类正确 |

通配地址（`:5178`、`0.0.0.0`、`[::]`）一律视为「暴露」，否则警告会在
最需要它的场景下沉默。

## 三、已知但未修的暴露面

这些不是本次引入的，但上线前应知道：

1. **凭据明文落盘（有意识保留）。** `requests` 与 `history.request_snapshot`
   都含明文 `auth`（实测确认）。拿到数据库文件就能读出全部凭据。文件权限
   挡的是「同机其他账户」，挡不住「文件被复制走」。

   **2026-10-21 决定暂不加密**：当前是本机调度工具，数据库不离开这台机器，
   加密的主要收益不成立。备选方案（首选 DPAPI）、信任边界与实现要点已留在
   TODO 中，触发条件为「文件可能被复制走 / 多人共用 / 部署到不受信网络」。
2. **token 走明文 HTTP。** 它是 bearer 凭据，在不受信网络可被嗅探。
   需要 TLS 终结。
3. **SSRF 是设计特性，不是漏洞。** 工具本身就是请求任意 URL。但配合
   「发布 mock」时就变成：调用方能借所有者身份访问内网。DR-003 已在
   origin 变化时剥离凭证，边界是正确的。
4. **`/API/*` 与 `//api/*` 返回 HTML 200。** 实测确认**不泄漏数据**
   （Content-Type 是 `text/html`，是 SPA 首页，不是 API 数据）。
   只是与 `/api/*` 返回 JSON 401 不一致，属低危，可留。
