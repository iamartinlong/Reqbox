## P1 · 待决策

### [x] 项目改名　`已完成`　apimock → reqbox

**已执行（2026-10-21）**：项目、Go module、二进制、环境变量、数据库路径、
前端存储键全部统一为 `reqbox`。

**为什么选 `reqbox`**：直指 request，与 UI 的 Requests 一致，短、好拼、
终端里好敲。核查过 pkg.go.dev / npm / GitHub，未发现同类占用。

**被否决的候选**：

| 候选 | 原因 |
| ---- | ---- |
| `patchbay` / `shunt` / `spigot` | Go 生态已大量占用 |
| `apibench` / `apiforge` / `apibay` | 已有同名产品 |
| `airlock` | 已有同名 HTTP 客户端，定位几乎重复 |
| `FetApi` | `Fetapi` 是真实姓氏（GitHub 上多个个人仓库挤占搜索）；且 Go module 路径必须全小写，`FetApi` 会被静默改成 `fetapi` |
| `SuperGet` | **是 Getnet（桑坦德集团）的注册品牌**，Google Play 上有同名支付应用；且未表达「本地保存 + 可发布 mock」 |

**改动范围**：42 个文件、142 处引用，三种大小写分别映射：

| 原 | 新 | 用途 |
| -- | -- | ---- |
| `apimock` | `reqbox` | module 路径、import、二进制名、文件名、数据路径、存储键 |
| `ApiMock` | `Reqbox` | 文案、UI 标签、`<title>`、User-Agent |
| `APIMOCK` | `REQBOX` | 环境变量名 |

**必须一并处理的数据兼容（已实现并验证）**：

1. **数据库路径回退**。默认库名变了，且配置目录也从 `apimock/` 迁到
   `reqbox/`——这是两个不同的位置，只查同目录会漏掉。
   `legacyDBPath` 处理同目录改名，`legacyConfigDBPath` 处理目录迁移。
   新库已存在时优先新库，避免用户主动重开后又被拉回旧数据。
2. **环境变量回退**。老部署的启动脚本仍写 `APIMOCK_*` 也能用；两者都设时
   新名优先。
3. **localStorage 回退**。`theme` / `session` / `language` 三个键。
   `index.html` 里的内联脚本也读旧键，否则升级用户每次加载都会闪一下错误主题。
   读到旧值后立刻复制到新键，回退只走一次。

**验证**（实测，不只是测试）：

| 场景 | 结果 |
| ---- | ---- |
| 目录里只有 `apimock.db` | 日志显示 `using database ... apimock.db`，读出 43 请求 / 76 历史，**未新建** `reqbox.db` |
| 新库已存在 | 优先使用 `reqbox.db` |
| 旧环境变量 | `APIMOCK_ADDR` 生效，新名优先 |
| localStorage | 11 个用例覆盖回退、复制、优先级 |

**顺带加了启动日志 `using database <path>`**：改名之后，这是判断「找到数据了」
还是「悄悄用了空库」的唯一外部依据。

**验收**：

- [x] 全新克隆能 `go build` 且 `go test ./...` 全绿
- [x] 老数据库仍能被打开（实测 43 请求完好）
- [x] 老 localStorage 的主题与设置仍在
- [x] 构建脚本产物名与新名一致

**遗留**：仓库迁移到 GitHub 并以全新状态发布（见 [PLAN](./PLAN.md) 的 1.1）。
代码与构建都不依赖仓库名，所以这不阻塞使用。

### [x] 历史快照中的凭证为明文　`方案 A 已完成`　方案 B 已决定**暂不实现**

`requests` 表与 `history.request_snapshot` 均以明文保存 Bearer / Basic /
API Key。这是「能重放」的前提，脱敏不能解决问题。

- **方案 A（已完成）**：保留明文，收紧数据库文件权限，并用 token 控制谁能
  调用 API。
- **方案 B（暂不实现，见下）**：主密钥加密 `auth` 字段，重放时解密。

**实施过程中发现的两点**：

1. `os.Chmod(0600)` 在 Windows 上**不设 ACL**，只切换只读位。原计划里的
   「收紧到 0600」在主要部署平台上等于没做。改用 `SetNamedSecurityInfo`
   设置 DACL，并用可继承 ACE 让 SQLite 自己创建的 `-wal`/`-shm` 也受限。
2. 比文件权限严重得多的是：`GET /api/requests` 无需任何凭据就返回明文
   token，而默认监听 `:5178`。文件权限防「同机其他用户」，防不住
   「同网段任何人」。因此补了 token 鉴权（见 DR-006）。

#### 为什么暂不实现（2026-10-21 决定）

当前定位是**本机调度工具**，数据库文件不离开这台机器，加密的主要价值
（防「文件被拷走」）在这个前提下不成立。引入密钥管理会带来新的故障模式：
密钥丢失、重装系统后无法解密、启动时索要口令——收益不抵复杂度。

**何时重新考虑**（任一成立）：

- 数据库放在同步目录（OneDrive / Dropbox / 网盘）或会被备份外发
- 多人共用一个实例
- 部署到不受信网络

届时若要做，**首选 DPAPI**（`CryptProtectData`，`golang.org/x/sys/windows`
已提供，无新依赖），而不是自建密钥文件：

| 做法 | 解密方式 | 挡住 | 挡不住 |
| ---- | -------- | ---- | ------ |
| DPAPI | 系统按当前 Windows 账户自动解密 | 拷走文件、同机其他账户、同步泄露 | 以该账户身份运行的恶意程序 |
| 主口令 | 启动时输入并派生密钥 | 同上 + 同账户离线拷贝 | 口令被写进启动脚本（常见结局） |

**DPAPI 的前提是「登录会话即信任边界」**，所以它挡不住「已能在你账户下
执行代码的人」。这一点必须在实现时写进文档，否则是虚假的安全感。

#### 实现时必须一并处理的点

1. **历史快照同样要加密**——`history.request_snapshot` 里也有明文 `auth`，
   漏掉等于没做。
2. **导出保持明文**——导出用于跨机恢复，加密后换机就解不开。这意味着
   导出文件比数据库更敏感，需要在导出时提示。
3. **解密失败要降级，不能崩**——密钥丢失时标记「无法解密」，列表照常显示，
   发送时提示重新输入凭据。静默清空会让用户以为数据全丢。
4. **Unix 分支要诚实**——若不做 keyring，就明确报「不支持加密」，不要假装。

预估 1.5 天（比原估 2～3 天少，因为不需要第三方 KMS）。

#### 更便宜的替代（若只想防误发）

约 0.1 天：启动时检测数据库是否落在同步目录并警告；导出时二次确认并说明
「文件含明文凭据」。覆盖「误发文件」这一最常见的意外，且不引入新故障模式。

## P3 · 功能

### [x] 多语言（中文 / English）　`1～1.5 天`　已落地 268 条文案、19 个用例

当前界面文案为英文。要支持中英切换，需抽取全部文案 + 语言选择 + 持久化。

**范围**：不只响应区标签，还包括 `Params / Headers / Body / Auth / Publish`、
侧栏、对话框、toast、状态提示等全部用户可见文本。

**验收**：

- [ ] 切换语言后无需刷新即生效
- [ ] 选择被记住（localStorage）
- [ ] 无遗漏的硬编码文案（可用脚本扫描 JSX 中的中英文串）

### [x] 阶段耗时（DNS / TCP / TLS / 首字节）　`0.5～1 天`

目前只有总耗时。「慢在哪」比「总共 800ms」更有用。

实现依赖 `net/http/httptrace`，需在历史表新增分项字段（迁移追加）。

**验收**：响应区可展开看到各阶段毫秒数；历史记录可回溯。

### [x] 完整 URL 可见性　`0.3 天`

URL 输入框为单行 `<input>` 且 `overflow-x: clip`，无 `title` 兜底。
实测 638px 宽时内容需 1082px，**444px 被裁掉且无法查看**。

**验收**：长 URL 可通过悬停或展开查看全文。

### [x] 查询参数去重　`0.1 天`

URL 中已手写 `?q=1`，params 里又配了 `q=1` 时，最终变成 `?q=1&q=1`。
当前行为是两者独立追加。

**需要先决定**：去重（后者覆盖前者）还是保持现状（明确文档说明）。

### [ ] SSE 支持　`1～1.5 天`

流式读取响应并增量渲染。相对 WebSocket 容易。

### [ ] WebSocket 支持　`3～5 天`

需要独立的连接管理界面（收发消息、连接状态、心跳），工作量显著。

### [ ] Mock 转发调用方请求体　`0.5～1 天`

已发布端点固定使用保存的 body，调用方 payload 被忽略。
需区分 Mock（固定响应）与 Proxy（透传）两种模式。

### [ ] 请求链式调用 / 前置换算　`2～3 天`

无法「先登录拿 token，再带着 token 请求」。需要从响应提取变量并注入后续
请求，涉及依赖顺序与失败传播的设计。

## 已修复（供检索，不必重做）

- TLS 校验可被静默关闭（`verifyTls` 缺省为 false）
- Mock 会把保存的凭证发给调用方指定的主机
- 跨站写入（CSRF）：无 Origin 校验
- 请求无法移回「未分类」（`collectionId: null` 被忽略）
- 导入会静默清空整个工作区，且无确认
- 原生 `prompt` / `confirm` 在部分环境不可用或样式不一致
- 新建草稿因空时间戳导致 400
- 发布 mock 时未填 slug 会产生不可访问的端点
- 切换请求时响应区残留上一个请求的结果
- 请求地址栏比 SEND 按钮矮 13px
- 对话框底部按钮贴边 / 溢出卡片
- 请求头从未捕获（看不到自动添加的 Content-Type / Authorization 等）
- 失败时 URL 显示未解析的 `{{变量}}` 模板
- 标签选中态从未生效（`data-active` 变体未定义，下划线 0px）
- 重组标签时丢失 Received 时间与 Cookies 列表
